## 必须守住的实现规则

1. **密钥仅后端。** 使用 Functions Secret Manager 配置 `ANTHROPIC_API_KEY`、`DEEPSEEK_API_KEY`。不能用VITE变量、浏览器供应商请求或在日志／仓库／聊天暴露key。模型ID由后端配置，实施时核对官方文档与实际账号支持；特别检查DeepSeek备用模型能否真正处理照片，不能把图片路径当文字算识图。
2. **有限主备。** 一次请求最多Claude一次、DeepSeek一次，顺序调用；总截止75秒、单家最多30秒是设计默认值。网络／429／5xx／超时／结构错误才转备用；缺金额、模糊或分类不明应留给用户补，不靠反复调用猜。两家都失败保留内容与手动填写入口。
3. **模型不能进 Firestore 事务。** 短事务取得持久租约，事务外调用，带attempt令牌和inputRevision回写。迟到响应不能覆盖新草稿。普通账务客户端只有15秒超时，AI要用专用长请求／状态订阅，不得通过自动reconcile重复计费。
4. **确认保存整单原子完成。** 服务端重算并校验已保存的revision，在一个事务中写明细、关联、可选库存、审计和committed回执。同draftId即使用不同operationId也只写一次；成功断线后返回原回执，不重建单。
5. **折扣只记一次。** 金额整数sen，最大余数法分摊，原收据总额保留。receipt父记录不是额外支出。不把付款100／找零48算成新的成本。私人行保留证据、标记不入营业账；原全单折扣先分摊再排除，不能让剩余营业项目多摊折扣。
6. **接入现有边界。** 已关账日期、月租归属与唯一槽、工资条件、开档付款关联、作废与未付款口径继续生效。普通经营支出不能误算开档成本；既有钱箱资金往来入口不重新加回来。
7. **私有图片。** 本店owner权限、限定对象路径与bucket、最多5张／每张10MB、JPEG／PNG／WebP、服务端验证mime与字节。不能接受任意URL抓取，不能用公开长期token URL；识别／记账后的原图不能被替换。清理策略区别草稿附件与已入账凭证。
8. **真实统计与缓存。** 聚合已有有效支出，不重复加receipt和batch；欠款结清只改付款维度。缓存依据包含付款、作废、费用归属与相关政策的数据摘要，账目变更后旧解读不能假装最新。引用ID和数值由后端验证。
9. **模拟仅用于测试。** HTML原型、收据SVG和示例答案是设计资料，不能复制成正式AI逻辑或灌进真实店账。Emulator可用mock provider；生产无密钥时明确未配置，手动录入仍可用。
