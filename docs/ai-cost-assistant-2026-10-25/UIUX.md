# 豪云吞面 · AI 记成本 UI/UX 设计

2026-10-25。依据已确认的设计：Claude 默认、DeepSeek 备用、用户可改结果后确认保存。原型是独立演示，不调用模型、不连接 Firebase、不持久化真实账目。

## 页面与入口

现有收支导航保留；「食材与用料」改称「AI 记成本」。页面内分为「记一笔 / 采购记录 / 开销分析」，不新增第三层菜单。收支总览「记一笔支出」进入同一录入入口。

首屏只突出一个任务：记录今天买了什么。批次、开始使用、结束旧批、损耗和核算范围放在「详细用料管理」，普通录入不经过这些表单。

## 主要流程

输入图片或句子 → AI 整理 → 核对并修改 → 一键确认保存 → 查看记录。

步骤指示为「1 输入 / 2 核对 / 3 保存」。模型输出不是账目；用户未确认前可安全返回、删除草稿、离开后续编。保存期间保持按钮状态，结果不明时查询同一草稿，不让用户重新记一笔。

### A. 文字录入

桌面中心为输入卡，右侧为今天采购摘要、最近草稿及使用提示。输入框示例为「今天买了葱10块、肉碎32块、煤气35块，都付了」。快捷示例只帮助填入文字，不直接记账。

输入后点「帮我整理」。加载显示「正在整理项目、金额和分类…」；不用虚假的精确百分比。切换备用服务时继续保留输入，只有确实耗时较长才提示「正在尝试备用服务」，不要求用户选模型。

### B. 收据录入

「拍照 / 上传收据」支持手机相机和文件选择；电脑支持拖放和文件选择。先展示缩略图、页码、删除 / 补拍、旋转与查看大图。5 张、每张 10 MB 为上限；第一版仅 JPEG / PNG / WebP，HEIC / PDF 说明需转换，不能静默忽略。

上传后点「识别这张收据」。光线差、文字模糊、非收据时保留图片并说明哪部分需补拍；不把识别错误假装成服务故障反复调用备用模型。

### C. 结果核对

桌面左侧固定来源区（原话或收据预览），右侧编辑。手机先显示可收起的来源卡，再显示明细卡，不强迫横向滑动表格。

每项主字段仅「项目 / 分类 / 金额」，可删除；「补充数量、单位或备注」按需展开。全单日期和付款状态在清单顶部。混合付款可展开每项付款状态覆盖。未知分类显示「请选择分类」，可选其他；金额不清显示空白及具体提示。

原话明确「都付了」可预填已付；否则显示「是否已付？」并在保存前确认。付款来源默认「未说明」，放在可选资料里。没有数量仍可保存，不出现阻止保存的库存红色错误。

底部操作条固定：左侧「共 3 项 / 合计 RM77.00」，右侧「确认保存 RM77.00」。只有一项明确的主要按钮。按下后为「正在保存…」，成功前不关闭页面。

用户增删改后立即重算；原始识别结果及图片保留。重新识别必须明确选择应用新结果，不能覆盖用户的修改。

### D. 收据差额

默认显示明细小计、整单折扣、税费、计算总额和收据原总额。优惠及税费按明细毛额以确定的整数 sen 规则分摊，页面解释「折扣已分摊到明细，只记录一次」。

差额时显示「与收据相差 RM3.00」，提供「查看原图」和「说明并采用修改总额」。后一项必须写原因并确认最终总额；之后再改金额会使原确认失效。原收据总额永不改写。

未平账或未确认差额时保存不可用，差额和解决动作就在合计附近。不能用整单总额代替不清楚的每行金额，也不能悄悄新增“其他”凑平。

### E. 保存成功与记录

成功显示「这笔记好了」、金额、项目数和去向：「2 项食材采购 / 1 项日常费用」。数量未知的说明为「采购已记账，用量可稍后补」，不显示假的库存数量。

提供「继续记一笔」和「查看这笔记录」。不提供无审计的删除或撤销；已保存数据更正走原有作废 / 更正流程。原文、原图、用户最终内容和账目关联可从记录详情回查。

采购记录默认按购买日展示，支持名称搜索、日期和分类。显示已付 / 待付、金额、录入来源、数量待补标记；补数量只是给原采购补库存资料，不生成新支出。

### F. 开销分析

首屏为真实账本统计卡、分类分布及「问问这段开销」。快捷问题为「这个月花在哪」「比上月多花在哪里」「有哪些待付款」。默认本月，可改日期。

回答按「结论 → 金额依据 → 可打开的记录」展示，并附区间、生成时间、资料完整性。没有数据时提供录入入口，不生成示范结论当真实分析。

没有数量时描述采购开销，不说单价上涨；没有消耗资料时不推断浪费、剩余量或实际单碗成本。API 失败时保留确定性统计表，文字解释显示稍后重试。

## 异常与反馈

| 情况 | 界面行为 |
| --- | --- |
| 无网络 | 保留本次输入；提示联网后整理；手动记账仍遵循系统原有在线条件 |
| Claude 暂不可用 | 自动有限尝试 DeepSeek，用户无需操作；结果仍须核对 |
| 两家都失败 / 未配置 | 保留原文和图片，提供重试、手动录入；不能显示成功 |
| 重复收据 | 提示日期、商家、金额、原记录；可查看，确实另一笔则明确确认并说明 |
| 保存已成功但断线 | 查询草稿提交状态，展示原回执；不创建新单 |
| 草稿被另一页面修改 | 提示已有新版本，先载入或另存，不能静默覆盖 |
| 包含已关账日期 / 重复月租 | 指明对应行，整单不保存，提供修改或现有更正流程入口 |
| 明确外币 / 退款 | 提示本期处理范围，保留识别内容并进入手动对应流程 |

## 视觉与响应式

- 沿用奶油底 #f5f3ed、白卡 #fffefa、砖红 #a93824、松绿 #2c614b；不引入紫色 AI 渐变和大面积聊天气泡。
- 系统字体 Segoe UI / Microsoft YaHei / PingFang SC。桌面主标题 28–32 px、正文 14–16 px、次要信息不小于 12 px；手机输入框正文 16 px。
- 主要触控目标不小于 44 px，间距 8 px 以上。输入保留可见标签；金额右对齐并用等宽数字。
- 1440 桌面：侧导航 + 主内容，核对页来源 / 编辑双栏；1024 平板：收窄导航，编辑区优先；768 与以下折叠来源；390 / 375 手机：单列、明细卡、底部固定保存条，预留安全区和滚动底边距。
- 页内滚动时不丢失保存动作，软键盘打开时仍可访问当前字段与底部动作。放大 200% 不遮住主要操作。
- 原生表单、可见焦点、错误与字段关联、状态 aria-live、对话框焦点约束和关闭后焦点返回；prefers-reduced-motion 下关闭装饰动画。

## 原型与正式实现的对应

`mockup/index.html` 可直接打开，场景选择器只用于评审，不属于正式产品。文字 / 收据识别、备用接手和分析回答都用内存示例；真实上传图片仅本机预览，原型不会读取其文字。

截图用于布局和交互参考。正式代码复用现有 React 组件及金额 / 账本规则，不能把原型示例数据或模拟分析代码复制进正式系统。
