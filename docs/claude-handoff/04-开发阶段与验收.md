# 04 · 开发阶段与验收

本文件是Claude的开发阶段边界与验收要求。它不代表已有测试执行结果。实现者需先读全部规格，再根据实际仓库产出任务列表；每阶段交付能运行、可核验的结果，不能只完成新UI。

## 1. 阶段与交付物

| 阶段 | 范围 | 必须交付/退出条件 |
|---|---|---|
| A 基线与领域 | 现状核对、版本锁定、金额与菜单模型、时间与财务纯函数 | 可重复安装；原有正确用例保留；新规则测试；差异决策记录 |
| B UI与工作流程 | 设计Token、布局、POS配置/购物车/收款、订单/KDS/老板页面 | 五视口可用；中英完整；加载/空/错/离线组件；使用可替换数据层 |
| C 云端营业闭环 | Auth/角色、Firestore模型/Rules/索引、命令、实时厨房、餐牌/收款 | Emulator完整接单→厨房确认→制作→出餐→回收；权限与并发测试通过 |
| D 离线单机营业 | PWA壳、IndexedDB原子收单、日志、人工传单、重连/核对 | 真断网+刷新+出餐+回收+补同步；不重收、不重做、不丢单；恢复包可重入 |
| E 财务与关账 | 进货/损耗/退款/资金往来、报表、ROI、日结、CSV | 日历/营业日/跨日退款/成本不重复、冻结/迟到调整测试 |
| F 测试云与试营业 | staging部署、实机、权限、监测、备份演练 | 两台物理设备联调；一周模拟营业数据/用量核验；问题清单处理 |
| G 生产切换 | 账号配置、计费、域名、生产部署、开档 | 项目/region/Rules证据、演示数据为零、回滚与纸单流程、owner验收 |

先完成A/C关键路径再把全部页面精修；B可先做局部静态/假数据预览，但不能拿假数据演示替代C/D。离线收单是首版必需，不放到上线后“再接”。无需引入无关的框架重写。

每次开发更新 `docs/implementation-status.md`：当前阶段、完成项、未完成项、修改文件、实际运行的命令及结果、手工验证、待用户配置、下次入口。重大业务变更同时改本交接规格。

## 3. 在线端到端与并发

| ID | 操作 | 预期 |
|---|---|---|
| O01 | 现金应收RM18，实收RM20 | 找零RM2；只有最终确认后产生支付与厨单 |
| O02 | QR仅选择方式/展示二维码 | 不能自动变已到账；必须人工确认 |
| O03 | 提交连续点10次/客户端超时重试 | 一张订单、一条支付、一个牌锁、一份成本；返回同ID |

| O06 | 出餐18号后立刻新开单18号 | 仍不可用；实体回收后才可用 |
| O07 | KDS两设备同时出餐/一台撤回一台取消 | 版本/状态校验，单次生效；过期操作明确提示 |

| O12 | 新营业日仍有昨晚未完成单 | KDS继续显示，保持原业务归属日期 |
| O13 | 未出餐与已出餐收据打印 | 只打印真实时间/状态；打印失败不重建订单；副本有标记 |

## 4. 离线必测场景

使用浏览器工具断网和关闭实际网络两种手段，不能仅手改一个 `isOffline` 布尔值。另模拟Functions超时但Firestore可读、Auth过期、数据库权限拒绝等半断连情形。

| ID | 场景 | 验收 |
|---|---|---|
| D01 | 主机已开档→断网→现金接单→刷新/关闭重开 | 已收订单、草稿、占牌、序号均恢复；显示本机未同步 |
| D02 | 存储配额不足或IndexedDB失败 | 不报成功、不丢购物车；可查看失败与导出恢复材料 |
| D03 | 离线接单→人工交接→人工出餐→回收→同牌新单 | 日志有序；联网最终牌归属正确，旧单不抢新牌 |
| D04 | D03恢复网络，重复上传每条10次 | 订单/付款/成本/审计业务事件各一份；不自动送厨/重打 |
| D05 | 离线单尚未制作→联网 | 独立人工待核对，不进入电子批次；人工核实转电子后才发送 |
| D06 | 上传成功时关页，响应未保存→重开 | 按稳定ID恢复结果，不重复应用 |
| D07 | 重连中网反复抖动/事件缺号/乱序 | inbox保留、明确阻塞、可重试；不越过牌和订单依赖 |
| D08 | 离线期间主机被更换epoch | 旧机日志仍可上传待核对，禁止自动接纳/覆盖新主机数据 |
| D09 | 离线旧价成交后线上菜单改价/售罄 | 按已验证历史版保留原成交，版本差异可见；未知版本隔离 |
| D10 | 时间回拨10分钟/跨04:00/离线超班次24小时 | 显示时间质量与营业资格异常，不伪造SLA或新云授权 |
| D11 | 离线QR无另一个可核验收款端 | 不允许声称到账；外部真实核验需显式记录 |
| D12 | 设备重登/两个标签页/导出后重复导入 | 登录后承接原日志；单写端；重复导入同eventId不重复入账 |
| D13 | 云端关账后才恢复离线单 | 保留已收事实，进入关账后待调整；原关账版本/旧CSV不变 |
| D14 | 在线提交结果不明后网络中断 | 不能用新ID复制成人工单；核对厨房与原operation后继续 |

## 5. 财务、日期与精度

固定样本：某日现金收8000sen、QR收4000sen、已退现金1000sen、已分配BOM35000成本单位（3500sen）、未重复损耗2000单位（200sen）、其他营业费500sen；若当日摊销2903sen，则净收11000sen，估算利润3897sen=RM38.97。

同日实际已付进货5000sen、备用金10000sen、钱箱付其他营业费500sen，无其他资金移动：经营现金净流入 `12000-1000-5000-500=5500sen`；钱箱应有 `10000+8000-1000-5000-500=11500sen`（进货确实从钱箱付出）。不得从现金流再次扣BOM/摊销。

| ID | 场景 | 验收 |
|---|---|---|
| F01 | 同样本改变报表周期 | 订单/损耗/费用一起正确筛选，不扣其他日期损耗 |
| F02 | 31天固定费用分配 | 前7天2904、后24天2903sen；合计90000 |
| F03 | 收款后待做取消/制作后取消/出餐后退款 | 支付独立；待做成本可反转，已耗材成本保留，退款只记录真实返款 |
| F04 | 订单取消报废再登记损耗 | 同一份BOM不重复扣除；仍能看到损耗数量 |
| F05 | 次日退款 | 减退款日净收，保留原销售日与出餐样本，可追踪关联 |
| F06 | 同月支付房租 | 现金流扣付款，经营只扣摊销，不再扣一次整笔房租 |
| F07 | 0单/0对比期/0资本/亏损 | 比率显示—或明确不适用；无演示期初/不吞亏损/不除0 |
| F08 | 479999/480000/719999/720000ms | 正常/偏慢/偏慢/超时；达标只含第一项 |
| F09 | 239999/240000ms | 极速/正常；先用毫秒分档再格式化 |
| F10 | 4个有效耗时3/5/7/9分 | 平均6、中位6、P90=9、达标75%；无效时间和未核对离线样本排除 |
| F11 | 开关账并发新交易 | 写屏障/水位保护；迟到事项明确待调整，不静默遗漏 |
| F12 | CSV含中文、逗号、换行、=开头备注 | 编码、转义和公式注入防护正确；合计可与日结核对 |

## 6. 权限与安全测试

用Firebase Rules测试工具和Emulator分别构造匿名、其他门店、kitchen、cashier、owner、已停用成员。验证读取矩阵；任何人不能直接客户端写交易。再直接调用Functions测试越权，确保Admin SDK路径也做权限检查。

恶意payload测试：前端改总价、改BOM、假storeId、复用operationId换内容、伪造二维码到账、越权退款、非法状态跳转、超长日志、跨门店orderId。后厨真实网络响应里不能出现售价/成本字段，不只检查界面隐藏。

生产清单：无test mode开放Rules、无服务账号私钥、无debug token、无演示重置、无自动注入mockData、无默认通用员工密码。Firebase Web配置可作为公开应用配置，但它不是数据库授权。

## 7. 实机和体验目标

- 视口按02逐一截图，中英文都验证；键盘/200%缩放/reduced motion可操作；无正文溢出、关键按钮遮挡。
- iPad/Android或实际目标设备验证48px触区、音效首次授权、PWA重启、本地存储、系统打印。
- 员工核心图卡触区至少56px；按06找不懂中英的代表员工做示范后任务测试，不用增加英文标签代替验证。断网后图片仍显示，面薄/细面/Kosong/走青在POS与KDS图卡一致。
- KDS真实距离约1.5米确认餐牌、数量、走青、Kosong能辨认；蒸汽/反光环境人工观察，不能只用桌面截图推断。
- 性能目标是试运行目标，不是供应商承诺：轻触视觉反馈≤100ms；热态接单API P95≤2秒、正常网络KDS收到P95≤2秒；冷启动单独测量并如实展示。失败时不能为了达标先画假成功。
- 负载场景：60张未出餐单、每单8行、两后厨设备、一主POS；数量汇总正确，滚动和计时不导致交互卡顿；历史订单分页。

## 8. Claude必须提交的上线证据

实际安装/测试/类型/构建命令及退出码；Emulator权限/事务/幂等记录；离线重启与恢复记录；五视口截图；staging URL与实际后端项目ID；生产Rules/region/owner初始化核验；账本样本与CSV对账；备份恢复演练结果；未完成限制和纸单预案。

用户尚未提供云权限时，列出准确待办和已完成本地验证，不得把 `firebase deploy` 命令文字当作真实部署成功。
