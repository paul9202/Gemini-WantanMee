版本：v2.1 图片优先设计基线 · 2026-10-22 · 中文

目标：把 Gemini 的单机演示原型升级为可实际营业的单档口系统，重新设计 POS、KDS、老板端，并接入 Google/Firebase。**本交接包是设计与开发输入，不代表新版已经实现或部署。**

后续已确认：员工可能不懂中文和英文，首版采用中文＋图片为主；以用户餐牌为菜单基准，启用细面/面薄，面价小RM7、中RM9、大RM11，Kosong半价RM3.50/4.50/5.50。门店展示使用餐牌名称「豪云吞面」。

## 怎样交给 Claude

1. 把整个 `docs/claude-handoff` 目录放进原项目，而不是只复制启动 Prompt。
2. 在 Claude Code 中打开项目，粘贴 `05-Claude开发Prompt.md` 中的「主 Prompt」。Claude 先核对仓库现状，再按阶段开发。
3. 第一阶段应交付可审查的代码与验证记录；之后按阶段继续。每次会话更新 `docs/implementation-status.md`，不要靠模型记忆承接。
4. 尚未提供 Google 项目及账号时，先完成 Emulator、本地功能和部署配置。开通计费、创建云资源、发布生产环境，需要用户提供相应账号权限并明确执行目标。

## 已选方案与边界

- 保留 React + TypeScript + Vite + Tailwind 路线；使用 Firebase Hosting、Auth、Firestore Standard、Cloud Functions 2nd gen。
- 本地模拟、测试云项目、生产云项目隔离；Google Sheets 只作后续导出目的地，交易数据库使用 Firestore。
- POS使用餐品图片与选项图卡、KDS使用相同图片与大餐牌号、老板端简洁经营报表。暖白/深墨岗位主题保持一致；视觉预览是假数据设计稿，功能与金额规则以Markdown规格为准。
- 首版：一个档口、一个指定可写收银终端、多台只读老板设备和后厨设备；保留 `storeId`，不做连锁 SaaS。
- QR 为人工核验到账的收款记录；未接银行/支付服务时，禁止显示「自动到账」。
- 首版利润称「估算经营利润」，不宣称经审计净利润。食材 BOM、现金流、回本分别展示。
- 不自动加入外卖平台、会员、复杂库存、AI推荐、蓝牙打印或其他语言整站翻译；语音留作扩展。首版中文＋图片，不能用增加翻译替代图片操作。
